## STEP 1 — EBIT 숫자 타이 확인 (최우선)

> **먼저 재보고 판정한다. 결론이 나기 전에 숫자를 고치지 않는다.**

### [작업]

1. Own acc. 열 하나만 골라, **PCR 표의 세로 계산을 한 줄씩 원문으로 뽑는다.**

```
순매출          = ?
 − 차감 항목 1   = ?
 − 차감 항목 2   = ?
 …
 = EBIT          2,193,185
```

각 줄의 **이름과 값**을 그대로 적는다. 합이 EBIT 과 맞는지 산술로 확인한다.

2. 그 표의 **원가 기준이 무엇인지** 코드에서 확인한다. BOM 스냅샷 전체 원가(15,487,170)인지, 그 일부인지.

3. 아래 둘 중 하나로 판정하고, 판정에 따라서만 손댄다.

- **(가) 기준 차이가 설계대로인 경우** — 코드를 고치지 않는다. 대신 화면·인쇄본의 PCR 표에 **원가 기준을 한 줄로 밝힌다.** 예: 어떤 원가를 기준으로 한 이익인지, BOM 전체 원가와 어떻게 다른지. 표 제목 옆의 `[샘플]` 표지는 그대로 둔다.
- **(나) 산식 결함인 경우** — 고친다. 고친 뒤 EBIT 이 **마진 1,548,717 이하**로 떨어지는지 확인한다. 원가 합계 ₩15,487,170 과 견적 ₩17,035,887 은 **변하면 안 된다**.

4. 어느 쪽이든 e2e 에 **타이 단언**을 넣는다 — "EBIT ≤ 견적 − 그 표가 쓰는 원가 기준"이 항상 성립하게.

### [자가검증]

- **성공조건**: 세로 계산이 원문으로 나오고 합이 EBIT 과 맞는다. (가)면 기준 문구가 화면에 실제로 보이고, (나)면 EBIT 이 마진 이하이며 원가·견적은 불변이다. 타이 단언이 e2e 에 들어갔다.
- **실패 시 진단**:
  - 원가·견적이 같이 변했다 → 되돌린다. 이 둘은 이번 청크에서 고정값이다.
  - (가)인지 (나)인지 판단이 안 선다 → **고치지 말고 세로 계산 원문만 회수하고 중단·보고.** 추측 수정 금지.
- **검증 명령**: 세로 계산 원문 + `pnpm -r test` 의 pcr 테스트 + `python scripts\demo_e2e.py` 의 S80 계열
