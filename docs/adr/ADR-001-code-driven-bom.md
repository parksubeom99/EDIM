# ADR-001: BOM 은 코드 관계에서 산출하고, 저장은 스냅샷으로만

- **상태**: 확정 (2026-07-06)

## 상황
주문생산 제품은 사양 조합이 수만 가지다. 초기 데이터 모델(DATA_MODEL)은 BOM/BOMLine 테이블을 두고 있었지만, 조합마다 BOM 을 저장하면 규칙 하나가 바뀔 때 저장된 BOM 전부가 틀린 채로 남는다.

## 결정
회사가 등록하는 것은 Sub 코드 · Product 코드 · 코드 관계 · 표 · 승인된 매크로뿐이다. BOM 은 `BOM Run` 이 규칙을 따라 계산하고, 결과는 `bom_code_run` 스냅샷(BOM 행 · 치수 · 카탈로그 지문 · 매크로 id · 개정)으로만 남긴다. 기존 BOM/BOMLine 은 이 스냅샷의 산출물로 재배치했다.

## 검토한 대안
- 조합별 BOM 저장 — 규칙 변경 시 대량 불일치
- 엑셀 파일 첨부 — 추적 불가

## 결과 — 얻은 것
규칙 변경에 강하고, 모든 BOM 이 '어느 규칙 · 어느 개정에서 나왔는지'를 품는다.

## 결과 — 치른 것
저장된 BOM 을 손으로 고치는 편의를 포기한다. 예외 BOM 이 필요하면 규칙(관계 · 표)을 고치고 다시 Run 한다.

## 검증
`backbone:test` · e2e S4~S20(코드 조립 → Run → BOM 11행 · 관계 추가 시 BOM 변화)
