# ADR-003: 산출물은 스냅샷만 읽고, 발행 · 발주는 DB 가 잠근다

- **상태**: 확정 (P6 · 0010 · 0011)

## 상황
원가 화면 · 견적서 · 구매 요청이 각자 다시 계산하면, 그 사이 단가나 규칙이 바뀌는 순간 숫자가 갈라진다. 또 승인된 BOM 과 발행된 도면이 서로 다른 치수를 가질 수 있는 구멍이 실제로 발견됐다(트러블슈팅 T-03).

## 결정
원가 · 도면 · 견적 · Tech Data · 구매 요청은 `runId` 스냅샷을 읽기만 한다. 치수도 스냅샷에 박는다(0011). 승인 · 발행 · 발주는 스냅샷 한 장에 묶이고(0010), 발행된 문서와 발주된 구매 요청은 DB 트리거가 수정 · 삭제를 거부한다.

## 검토한 대안
- 산출물마다 실시간 재계산
- 애플리케이션 코드로만 잠금

## 결과 — 얻은 것
견적 합계 = 원가 카드 = Word · Excel 값이 구조적으로 보장된다. 앱을 우회한 SQL 도 잠금을 못 푼다.

> **갱신 2026-09-30 (ccmd M-1 · 회장님 결정)** — 견적 단가 = 스냅샷 원가 × (1 + 마진율). 마진율은 PCR 요율표 파일(샘플 10%)에서 견적을 만들 때 읽어 견적 body 에 박는다(`margin` · 판 · 지문). **원가는 여전히 스냅샷 한 장에서 다시 세지 않고 읽으며**, 원가 카드 · PCR Full cost · 견적 적용 Table 합계는 바뀌지 않는다. 요율표가 없으면 마진 0 = 위 원래 규칙 그대로. 이 결정이 스냅샷 원칙(재계산 없음)을 바꾸지는 않는다 — 마진율도 만들 때 박히고 나중에 요율표를 바꿔도 이미 만든 견적은 그대로다(e2e S80c).

## 결과 — 치른 것
단가가 바뀌면 다시 Run 해야 새 견적에 반영된다(의도된 동작 — 옛 견적은 옛 단가를 유지해야 한다).

## 검증
`drawing:test` · `document:test` · e2e(견적 = 원가 = Office 파일 값 · 단가 변경 후 미재실행 시 옛 견적 불변 · 발행 후 수정 거부)
