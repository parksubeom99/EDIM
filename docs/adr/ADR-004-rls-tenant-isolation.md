# ADR-004: 회사 격리 = PostgreSQL RLS ENABLE + FORCE

- **상태**: 확정 (0002)

## 상황
여러 회사가 한 DB 를 쓴다. `WHERE tenant_id = ?` 를 한 곳이라도 빠뜨리면 다른 회사 데이터가 샌다. 코드 리뷰로는 누락 0 을 보장할 수 없다.

## 결정
모든 업무 테이블 `ENABLE + FORCE ROW LEVEL SECURITY`. 앱은 슈퍼유저가 아닌 `edim_app` 역할로만 접속하고, 요청마다 트랜잭션 안에서 `set_config('app.current_tenant', …, true)` 로 회사를 정한다. 새 테이블은 `tenant_id` + RLS 가 마이그레이션 규칙이다.

## 검토한 대안
- 애플리케이션 필터
- 회사별 DB · 스키마 — 운영비 · 마이그레이션 N배

## 결과 — 얻은 것
필터를 빠뜨려도 DB 가 0건을 돌려준다. 격리가 코드 품질이 아니라 DB 속성이 된다.

## 결과 — 치른 것
쿼리마다 트랜잭션 래핑 · 크로스 테넌트 집계(컨설팅)는 별도 설계가 필요하다.

## 검증
`rls:test` · 새 API 마다 e2e '다른 회사 404/0건' 단언 의무
