# Roadmap

## Phase 0: 제품 기준 정리

목표:

- 제품 방향 정리
- MVP 범위 결정
- 데이터 모델 초안 작성
- 화면 흐름 초안 작성
- 기술 스택 결정

완료 기준:

- 제품 정의 문서가 있다.
- 데이터 모델 초안이 있다.
- 첫 번째 MVP 업무 흐름이 정해졌다.
- 다음 구현 작업이 분명하다.

## Phase 1: SaaS 기본 골격

목표:

- 웹앱 생성
- 로그인/사용자 구조
- 회사 단위 데이터 분리
- 기본 레이아웃과 대시보드
- DB 연결

완료 기준:

- 사용자가 로그인할 수 있다.
- 회사별로 데이터가 분리된다.
- 고객과 프로젝트를 등록할 수 있다.

## Phase 2: CPQ MVP

목표:

- 품목 등록
- BOM 구성
- BOM 기반 견적 생성
- 견적 금액 계산
- 견적 상태 관리

완료 기준:

- 프로젝트 안에서 BOM을 만들 수 있다.
- BOM을 기준으로 견적을 만들 수 있다.
- 견적 총액이 계산된다.

## Phase 3: 문서와 승인

목표:

- 견적서 출력용 데이터 생성
- 기본 PDF 또는 Excel 출력
- 승인 요청
- 승인/반려 이력

완료 기준:

- 견적서를 문서로 출력할 수 있다.
- 승인자가 견적을 승인하거나 반려할 수 있다.

## Phase 4: PLM 기본 기능

목표:

- 품목 리비전
- BOM 버전
- 변경 요청
- 도면 파일 연결
- 자동 제작도면 생성 흐름의 기본 구조

완료 기준:

- 품목과 BOM의 버전을 관리할 수 있다.
- 변경 요청 이력을 남길 수 있다.

## Phase 5: ERP 커스터마이징

목표:

- 회사별 커스텀 필드
- 화면 표시 설정
- 코드값 설정
- 문서 템플릿 설정
- 승인흐름 설정

완료 기준:

- 회사 관리자가 프로젝트나 품목에 커스텀 필드를 추가할 수 있다.
- 기본 승인흐름을 회사별로 다르게 설정할 수 있다.

## Phase 6: AI 매크로

목표:

- 자연어로 매크로 초안 생성
- 매크로 검토/저장
- 제한된 작업 자동 실행
- 문서 초안 생성

완료 기준:

- 사용자가 자연어로 반복 작업을 설명하면 매크로 초안이 생성된다.
- 관리자가 검토 후 매크로를 저장할 수 있다.

## Phase 7: 운영 준비

목표:

- 보안 점검
- 백업
- 결제/구독 구조
- 모니터링
- 배포 자동화
- 장애 대응 문서

완료 기준:

- 실제 고객사가 제한적으로 사용할 수 있는 베타 서비스 상태가 된다.
