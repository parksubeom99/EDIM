## T-01 · 운영 빌드에서만 HTTP 500 `too many clients`

- **증상**: 개발 모드 e2e 287/287 통과. 운영 빌드(`next build → start`)로 같은 시나리오를 돌리자 중반부터 HTTP 500, PostgreSQL 로그에 `sorry, too many clients already`.
- **재현**: 별도 환경에서 `next start` + e2e, 실행 중 `select count(*) from pg_stat_activity` 가 계속 증가해 한도(100 → 300 으로 올려도 동일)에 닿음.
- **원인**: `packages/db/src/client.ts` 의 클라이언트 래퍼가 개발 모드의 핫 리로드 대비 캐시(`globalThis`)를 **운영 모드에서는 건너뛰고**, `Proxy` 가 **속성 접근마다** `new PrismaClient()` 를 만들었다. PrismaClient 하나 = 연결 풀 하나이므로, 쿼리마다 풀이 생겼다.
- **수리**: 모드와 무관하게 클라이언트를 항상 1개로 캐시.
- **결과**: 운영 모드 e2e 287/287 → 이후 348/348 · 동시 연결 14~17.
- **재발 방지**: 머지 게이트에 **운영 모드 e2e + 실행 중 연결 수 기록**을 추가([ADR-008](adr/ADR-008-production-mode-gate.md)).
- **배운 것**: "개발 모드 통과"는 운영 동작의 증거가 아니다. 캐시 · 번들 · 프리렌더가 다르다.
- 커밋: `d0f6cb0`

## T-02 · 한국 시간 새벽에 '오늘 유효 단가'가 '예정'으로

- **증상**: KST 00~09시에 단가 이력 화면에서 오늘부터 유효한 단가가 "예정"으로 표시되고, BOM Run 이 전날 단가를 씀.
- **원인**: "오늘"을 `new Date().toISOString().slice(0, 10)` 로 잘랐다 — UTC 날짜라 KST 00~09시는 **전날**이 된다.
- **수리**: 회사 시간대 기준 `businessToday()` 를 `app/lib/today.ts` 한 곳에 두고 모든 날짜 판정이 이 함수를 거치게 함.
- **재발 방지**: 새벽 경계 단위 테스트(`2026-09-26T15:21Z` → KST 09-27) · 날짜 코드 규칙([ADR-009](adr/ADR-009-business-date.md)).
- 커밋: `e30ab62`

## T-03 · 승인 안 된 치수로 도면이 발행될 수 있던 구멍

- **증상**: 없음(설계 대조 중 발견). BOM 이 승인된 뒤 치수 표가 바뀌면, 그 승인된 스냅샷으로 **승인된 적 없는 치수**의 도면을 만들 수 있었다.
- **원인**: 도면이 치수를 스냅샷이 아니라 **현재 카탈로그**에서 읽었다.
- **1차 수리**: 스냅샷의 카탈로그 지문과 현재가 다르면 도면 생성 409.
- **근본 수리**: 치수를 스냅샷에 박고(0011), 도면은 스냅샷 치수만 읽음. 치수가 없는 옛 스냅샷은 다시 그리기 422.
- **재발 방지**: `drawing:test` · e2e S30.
- 커밋: `93fd00e` → `ba53b80`

## T-05 · 도커 빌드에서만 설정 화면이 '로그인으로' 정적 페이지로 굳음

- **증상**: 로컬 빌드는 정상. 배포 킷(docker) 빌드에서는 `/setup/print` 등 설정 화면이 로그인 상태와 무관하게 로그인 페이지로 보냄.
- **원인**: 세션 함수가 `AUTH_SECRET` 검사를 `cookies()` 호출보다 **먼저** 했다. Next.js 는 `cookies()` 호출을 "요청마다 렌더" 표지로 보는데, 비밀값이 없는 빌드에서는 그 전에 반환돼 페이지가 **정적으로 프리렌더**됐다. 로컬은 `.env` 가 있어 드러나지 않았다.
- **수리**: `cookies()` 를 먼저 호출.
- **재발 방지**: 배포 킷 컨테이너에 e2e 334/334 를 돌리는 것을 검증 절차에 포함. 이미지에 `.env` 를 굽지 않음(`.dockerignore`).
- 커밋: `b687fd5`

<a id="t-06"></a>
## T-06 · 잘린 비밀번호 해시가 통과

- **증상**: 단위 테스트 작성 중 발견 — 해시 문자열 끝이 잘려도 비교가 통과할 수 있었다.
- **원인**: 비교할 때 scrypt 출력 길이를 **저장된 해시 길이**로 다시 계산했다. scrypt 출력은 앞부분이 같으므로, 해시를 잘라 저장하면 짧게 다시 잰 값과 맞아 버린다.
- **수리**: 출력 길이를 고정값(KEYLEN)으로 강제 · 형식(6조각) · 비용 인자 범위 · salt 최소 길이 검사 후 `timingSafeEqual`. 없는 이메일에도 같은 시간을 쓰도록 더미 해시로 비교(계정 존재 여부를 응답 시간으로 흘리지 않음).
- **재발 방지**: 해시 형식 단위 테스트.
- 커밋: `c59d331`

## T-08 · 학습 공식이 틀린 값을 냄 — Macro DSL 에 곱셈 우선순위가 없다
- **증상**: 학습 AI 가 찾은 `전고 = 케이싱 + 2 × 프레임` 을 DSL 로 적어 시험 실행하니, 2,500 이어야 할 값이 230,200 이 나왔다.
- **원인**: Macro DSL 의 사칙연산은 **우선순위 없이 왼쪽부터** 계산된다(파서가 한 단계 우선순위). `C+2*F` 가 `(C+2)*F` 로 계산됐다. 사람이 쓴 매크로에는 없던 모양이라 처음 드러났다.
- **해결**: 식을 적는 쪽(`learning/formula.ts`)이 곱하는 항을 괄호로 묶는다 — `=Var(LRN,casing_height)+(2*Var(LRN,base_frame))`. 문법은 바꾸지 않았다(이미 승인된 매크로의 의미가 바뀌면 안 되므로).
- **재발 방지**: verify 단계가 근거 도면 3장으로 시험 실행해 1 mm 안인지 본다 — 이 검사가 먼저 잡았다. 같은 날 "핀 피치(1.8~3.2 mm)를 1 mm 허용으로 맞히는 가짜 공식"도 단위 테스트가 잡아 설명력 가드(값의 폭 ≥ 허용 × 20 · R² ≥ 0.99)를 더했다.
